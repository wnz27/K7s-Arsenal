# Frame Budget：帧预算

## 目标

把目标帧时长分配给输入、逻辑、物理和渲染等系统，用逐系统测量找到慢帧的主要来源。60 fps 的总预算约为 `16.67 ms`，其他刷新率按 `1000 / fps` 计算。

## 核心规则

```text
start = now()
updateSimulation()
simulationMs = now() - start
start = now()
submitRendering()
renderSubmissionMs = now() - start
```

- 测量代表性重场景、慢帧和高分位帧时间，不只看空场景平均 FPS。
- CPU 渲染提交时间不等于 GPU 执行时间；可用时使用引擎或平台的 GPU profiler。
- 优化前后比较同一场景、视角、负载和测量窗口，优先处理最大的瓶颈。
- 测量代码自身也有成本，避免在每帧热路径制造大量分配。

## 动效分镜

1. 保存最近约 `52` 帧的输入、update、physics、render 数据，绘制堆叠柱状图。
2. 画出 `16.67 ms` 红色预算线，超过预算的帧显示掉落标记。
3. 制造周期性物理尖峰，显示当前总毫秒数和当前最大系统。
4. 教学数据可合成，但必须标注；真实诊断面板的数据须来自实际计时。

## 常见错误

- 把 CPU 提交时长当成 GPU 时长。
- 只测平均 FPS，漏掉卡顿尖峰和高分位慢帧。
- 在不同场景或不同负载下比较优化结果。
- 用硬编码数字声称已经优化真实项目。

## 验收

- 各系统数值来自真实计时或明确标注的教学数据，堆叠总量与帧总时长一致。
- 超预算帧能被识别，最大系统标记正确。
- 调整窗口和刷新率目标后预算线正确更新。
- 真实优化报告包含同场景前后数据，并区分 CPU 与 GPU 测量。
