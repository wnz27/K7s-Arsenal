# Object Pooling：对象池

## 目标

预分配并复用频繁生成和销毁的子弹、粒子或特效，减少运行期分配与垃圾回收压力。池不会减少活跃对象的更新和绘制成本。

## 核心规则

```text
bullet = pool.acquire()
if bullet:
  bullet.reset(position, velocity, lifetime)
  bullet.active = true
onExpiry:
  pool.release(bullet)
```

- 启动或加载阶段预分配预期峰值，容量从场景需求得出；教学演示可使用 `14` 个槽位。
- 明确耗尽策略：拒绝生成、回收最旧特效，或在非关键路径扩容，不能静默无限增长。
- `reset` 覆盖位置、速度、计时器、目标、监听器、材质和视觉标记等全部有状态字段。
- 释放时解除外部引用，避免重复释放和同槽位仍被旧引用使用。

## 动效分镜

1. 两条发射通道使用相同生成频率、速度和寿命，上方每次新建，下方从固定池取对象。
2. 实时显示累计分配、待回收对象和池中 `in use / capacity`。
3. 用槽位点亮表现对象复用，上方用短暂停顿表现 GC 压力。
4. 教学 GC 停顿须标为模拟，不能把脚本插入的延迟当作真实性能测量。

## 常见错误

- 复用时只重置位置，遗留上一任目标的计时器、监听器或颜色。
- 池耗尽后无策略，或在热路径隐式分配。
- 重复释放、释放后仍保留外部可读引用。
- 声称池化解决了绘制、透明叠加或更新成本。

## 验收

- 稳态运行不再为每次生成创建新对象，槽位数量符合容量策略。
- 同一槽位多次复用后行为与新对象一致，无旧状态泄漏。
- 耗尽、重复释放、过期和场景销毁路径均有明确处理。
- 性能结论来自真实分配和帧时间测量，而非演示中的模拟停顿。
