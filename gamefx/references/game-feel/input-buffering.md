# Input Buffering：输入缓冲

## 目标

在动作暂时不可执行时短暂记住一次按键，并在首个可执行帧触发。典型用途是落地前起跳、攻击恢复结束前排队下一次攻击。

## 核心规则

```text
if jumpPressed: buffer = 0.1
else: buffer = max(0, buffer - dt)
if canJump and buffer > 0:
  jump()
  buffer = 0
```

- 默认窗口约 `0.1 s`，按动作手感调整；过长会执行玩家已不再预期的动作。
- 记录按下边沿，不要把持续按住当成每帧新的缓冲输入。
- 动作触发后立即消费缓冲，保证一次按下只执行一次。
- 与土狼时间组合时，一个记录早按，一个允许晚按，分别判断。

## 动效分镜

1. 两名角色以相同轨迹跳跃，并在落地前约 `0.08 s` 同时再次按跳。
2. 无缓冲组忽略输入；有 `100 ms` 缓冲组在接触地面的首帧再次起跳。
3. 标记按键时刻、落地时刻、剩余缓冲时间和起跳结果。
4. 在关键阶段使用慢动作或时间轴，让「首个可执行帧」清晰可见。

## 常见错误

- 动作触发后未清零，一次输入执行多次。
- 把按住状态误当成按下边沿。
- 缓冲计时使用暂停或命中停顿中错误的时钟。
- 只检查按下当帧，没有真正保存动作。

## 验收

- 窗口内的早按在首个可执行帧触发，窗口外的输入被丢弃。
- 一次按下只产生一次动作，持续按住是否重复由独立规则决定。
- 与土狼时间组合不会制造额外跳跃。
- 命中停顿或暂停期间采用项目明确的输入时钟，不会永久卡住缓冲。
