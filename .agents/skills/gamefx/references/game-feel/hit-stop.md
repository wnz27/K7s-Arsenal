# Hit Stop：命中停顿

## 目标

攻击接触目标时，短暂冻结攻击者和受击者的移动与动画，让接触帧可读。常见时长为 `50–100 ms`，可按伤害调整；教学演示可放慢到 `120 ms`。

## 核心规则

```text
onHit(damage): hitStopRemaining = durationFor(damage)
update(dt):
  readAndBufferInput()
  if hitStopRemaining > 0:
    hitStopRemaining -= unscaledDt
  else:
    updateFighters(dt)
```

- 停顿作用于明确的参与者，不要默认冻结整个世界。
- 停顿计时使用不受冻结影响的时钟，并处理本帧越过结束点的剩余时间。
- 输入采集与缓冲继续；粒子、相机和 UI 是否继续应明确选择，演示中建议继续。
- 同一次持续重叠不能每帧重新延长停顿。

## 动效分镜

1. 两组使用相同挥砍时间轴和受击者，接触时刻完全一致。
2. 无停顿组直接穿过接触阶段；停顿组在接触帧冻结双方。
3. 火花、闪光和时间轴游标继续运行，显示冻结区间与时长。
4. 冻结结束后从同一动画进度继续，不重播整次攻击。

## 常见错误

- 全局 time scale 同时冻结菜单、网络或结束停顿的计时器。
- 停顿结束后丢失本帧剩余时间，导致时长随帧率偏差。
- 持续碰撞反复触发停顿。
- 输入在停顿期间被丢弃，恢复后动作不连贯。

## 验收

- 双方只在指定接触窗口冻结，结束后准确恢复动画进度。
- 火花、UI 和输入行为符合明确的时间域设计。
- 一次攻击对同一目标只触发一次停顿，不同时长下计时稳定。
- 暂停、低帧率和连续命中不会导致永久冻结或无限延长。
