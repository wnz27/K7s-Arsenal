# Texture Atlas：纹理图集

## 目标

把多张小图打包进一张纹理，并让精灵保存各自 UV 矩形。共享图集、shader 和材质状态的精灵可以进入同一批次，减少纹理切换。

## 核心规则

```text
uvMin = sprite.pixelMin / atlasSize
uvMax = sprite.pixelMax / atlasSize
uv = mix(uvMin, uvMax, quadUV)
color = sample(atlas, uv)
```

- 图集可从 `2048 × 2048`、每图周围 `2 px` padding 开始，实际尺寸按资源与平台限制调整。
- 使用过滤和 mipmap 时，按 mip 层级增加 padding 并外扩边缘像素；`2 px` 不是所有场景的保证。
- 图集元数据记录像素矩形、UV、枢轴和原始尺寸，注意纹理坐标 Y 方向。
- 材质、shader、混合模式或绘制顺序变化仍可能拆批。

## 动效分镜

1. 按固定混合顺序绘制 `24` 个精灵和 `6` 种图案，逐个高亮当前精灵。
2. 对照组使用 6 张独立纹理，顺序变化时切换绑定；图集组始终使用同一纹理。
3. 同步展示独立纹理或打包图集，并在下方时间轴划分真实批次。
4. 参考顺序可产生 `22` 次调用对 `1` 次调用；实际实现须读取 renderer 统计，不把参考值硬编码为结果。

## 常见错误

- 只改变 UV，却仍给每个精灵绑定不同纹理。
- 过滤或 mip 采样到相邻精灵，出现边缘串色。
- 忽视绘制顺序和材质状态，图集仍被拆批。
- 图集过大影响内存、更新粒度或低端设备兼容性。

## 验收

- 每个精灵采样到正确区域，缩放、旋转、mipmap 和过滤下无邻图渗色。
- 同图集且状态兼容的精灵真正合并批次，调用数来自真实渲染统计。
- 两种模式使用相同精灵顺序、位置、颜色和动画。
- 图集元数据与打包结果一致，尺寸变化后 UV 仍正确。
