# Time Slicing：时间分片

## 目标

把不需要每帧执行的昂贵决策分散到多个帧桶，同时让移动、动画和紧急响应保持各自需要的更新频率。

## 核心规则

```text
bucket = frameIndex % bucketCount
for agent in agents:
  if agent.id % bucketCount == bucket:
    agent.chooseTarget()
  agent.move(dt)
```

- 可从 `4–8` 个桶开始；参考演示用 `192` 个 agent 和 `8` 桶，每帧只更新一桶决策。
- 60 fps、8 桶时，每个 agent 每秒约重新决策 `7.5` 次；这是调度结果，不是必须参数。
- 用稳定 id 或哈希均匀分桶，避免昂贵 agent 集中到同一桶。
- 紧急事件使用独立预算或立即唤醒，不能等下一轮桶造成不可接受延迟。

## 动效分镜

1. 两组使用相同数量的 agent 和移动目标，对照组每帧全量决策，分片组每帧一桶。
2. 所有 agent 每帧继续向各自最新目标移动，只有决策时间不同。
3. 高亮刚完成思考的 agent，并绘制当前桶及每帧决策数量。
4. 成本条显示 `16.67 ms` 预算线；若成本是合成教学数据，明确标注，真实项目使用计时结果。

## 常见错误

- 把移动和动画也降到分片频率，造成卡顿。
- 分桶不均，某些帧仍然出现尖峰。
- 没有测量新增响应延迟。
- 紧急战斗反应也被推迟到固定桶。

## 验收

- 每桶每帧只执行预期决策，所有 agent 的移动仍逐帧更新。
- 每个 agent 的决策周期和最大响应延迟符合设计。
- 分桶在 id 变化、增删 agent 后仍保持相对均衡。
- 性能收益来自真实测量，演示合成成本不会被当成项目结论。
