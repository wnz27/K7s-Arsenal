# Z-fighting：深度冲突

## 目标

避免共面或距离过近的表面因深度缓冲精度不足而逐像素争夺可见性。修复应同时处理几何布局、相机深度范围和渲染偏移。

## 核心规则

```text
camera.near = 0.1
camera.far = requiredViewDistance
decal.position = hit.point + hit.normal * smallOffset
```

- 在满足近处裁剪需求的前提下，让 near 尽量远；让 far 只覆盖实际视距。`0.1` 是演示起点，不是所有项目的固定答案。
- 不把两个可见表面放在同一平面。
- 小贴花可沿法线抬起约 `1 cm`，再根据世界尺度和掠射角调整。
- 支持 polygon offset 的渲染器可从 `factor = -1`、`units = -4` 开始调试；具体 API、符号和效果以当前渲染后端为准。
- 偏移过大会让贴花悬浮，不能靠无限增大偏移解决问题。

## 动效分镜

1. 左右放置相同地面和黄色贴花，左侧共面，右侧使用 polygon offset 或小几何偏移。
2. 相机缓慢环绕并降低至掠射角，让深度精度问题更容易出现。
3. 左侧出现闪烁条纹时保留真实表现；右侧贴花应稳定完整。
4. 显示 `same plane`、`polygon offset` 和当前 `near / far`。
5. 教学演示不能把左侧故意随机闪烁当作真实深度冲突；应使用真实深度缓冲，或明确标注模拟。

## 实现要求

- 优先修复共面几何和不合理相机范围，再使用材质偏移。
- 检查透明材质、渲染顺序和深度写入；polygon offset 不是所有透明问题的通用修复。
- 在目标 GPU、API 和实际相机距离验证。不同深度格式与 reversed-Z 后端的表现可能不同。
- 对比组只改变偏移策略，几何、材质颜色、相机和时间保持一致。

## 常见错误

- 为看清近处物体而把 near 极端推向零，损害远处精度。
- 用过大的几何偏移掩盖共面，导致贴花漂浮或穿帮。
- 只在编辑器或单一设备验证，忽略目标渲染后端差异。
- 用随机透明度动画伪造 Z-fighting，无法验证真实修复。

## 验收

- 目标设备上，修复组在正视、斜视和掠射角均无可见闪烁。
- near 和 far 符合实际场景尺度，贴花没有明显悬浮。
- 对照组差异仅来自目标修复，关闭修复后能复现问题。
- 若环境无法稳定复现真实冲突，明确说明验证限制，不宣称已彻底修复所有后端。
