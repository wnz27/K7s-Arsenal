# 决策规则速查 — 技术写作手册

| 能力 | 一句话规则 |
|---|---|
| 写作启动与长期坚持的机制设计 | 坚持不了写作是反馈结构问题不是意志力问题——设计快速正反馈、降低难度、按存款模型管理前期无反馈的预期 |
| 写作驱动学习：知识内化检验机制 | 读过不等于学会——用复述/发表检验内化程度，暴露的知识缺口就是下一轮学习的输入 |
| 动笔前定位：说服自己、三问与场景元问题 | 动笔前先过说服自己门禁，再一句话答清三问——传达什么讯息、目标受众是谁、希望受众做什么 |
| 从选题到成稿的写作工作流 | 日常攒素材→SEO 调研差异化→半小时时间盒列提纲→先配图→心流写正文→与旧文互链 |
| 清晰表达训练与写作编程共通原则 | 把读者想象成入门者重写解释，每句话都表达本意、相似内容用相似结构——清晰是交流的美德 |
| 文章质量五维自评与改进框架 | 五维过检：动机真实、回答场景元问题、争取加分项、表达有代入感、结构总分总——逐项判定并产出改进动作 |
| 发布前审读与脱敏把关 | 发布前两道关：三遍审读（结构→遣词→读者视角）后转他人审校；脱敏四类（客户项目名/机密/同事/版权）逐项打勾 |
| 中文技术文章排版与配图规范 | 短句短段（3-5 行）、颜色字体字号不超过 3 种、中英文间留半角空格、图片克制且清晰、考虑移动阅读 |
| 传播最后一公里：物料、渠道与交互 | 发布前备齐三件套（SEO URL、70 字内引文、一幅引用图），先按定位选优先渠道再匹配扩展，发布后据积极反馈持续改文 |
| 技术翻译工作流：理解优先、功能对等与五技巧 | 理解是翻译的源头——先查证弄懂原文，再按准确>易读>风格取舍，五技巧处理结构，脱稿以陌生读者身份校对 |
| 写一本书的工程方法 | 先接受公益情怀预期再开工：自上而下骨架、每章一迭代约一月交编辑、找尽可能多的初学者试读、技术书优先电子版 |
| 写作工具链：纯文本、版本管理与资产同步 | 以最小化写作干扰选工具——Markdown 单文件写初稿、Git 管理全程、代码与图源文件直接引用保持同步 |
| 负面反馈与流量焦虑的分类应对 | 先分类再行动——误解类视影响决定澄清（勘误是职责），恶意类无响应义务；用反馈漏斗与叫好叫座双体系校准流量预期 |

> 速查只给结论；需要原文依据、案例或反例时读对应能力卡。
