# 技术翻译工作流：理解优先、功能对等与五技巧

## R — 原文

> "如果将人工翻译的过程拆解开，那就是阅读原文、理解原文、输出译文。……对原文的理解才是翻译的源头。"
> ——《翻译这件小事》（王静源）

> "我们的目的是将原作的知识和信息准确、清晰地传达给目标语言的读者（以读者为中心），首先是重现意义，然后是风格。那么我们能得到这样的优先级排序：准确、易读/易懂、尽可能还原作者的风格。"
> ——《翻译这件小事》（王静源）

## I — 自述

翻译是三步流水线：阅读原文 → 理解原文 → 输出译文。市面上翻译理论几乎全聚焦"输出"，但真正的源头是理解——译者自己没弄明白就照搬表达，读者的混乱只会更高。好消息是非文学技术文本表意清晰、歧义少，理解门槛远低于文学翻译。翻译同时是"比精读更精的精读"：为保证准确必须不断追问"作者为什么这么说"，查术语查背景越跑越远——所以选材一定要是自己感兴趣的领域，否则对抗不了枯燥。

取舍判据是奈达的"功能对等"（以读者为中心）：**准确 > 易读/易懂 > 尽可能还原作者风格**。直译意译本无高下——直译保原味但易出翻译腔，意译融合但丢风格；当直译结构十分不符合中文表达习惯时，在保住准确的前提下选意译。

输出环节五个技巧：
1. **不受困于词性**：词性是语言表层结构，英汉表层差异大——原文名词可译动词、形容词可译名词；
2. **切分、合并、移位**：按汉语习惯拆长句、合并冗余同义、调整词组从句顺序（短句化利于理解，但错误率升高、易失原味，自由度由译者把控——短句是否一定好"尚存争议"）；
3. **被动处理**：被动转主动时汉语可省主语；保留被动时"被"字常可省略或换"受/遭/让/叫"，避免"被"字连篇；
4. **增词不增意、删词不减意**：增词为解释原意或加衔接词，删词为去英语语法冗余（代词/连词/介词不必逐词译出），铁律是不增减意思；
5. **脱稿校对**：译完必须校对，且脱离原稿、以陌生读者身份看译文是否达意——翻译时觉得正常的表达，校对时常发现完全不通。

项目维护：术语表持续维护保证译语统一（多人合作尤其关键）；格式/注释/术语等细节不积压到最后（最后校对大概率不会再逐句对照原文）；翻译时间尽量整块，效率与专注度正相关。

## A1 — 应用示例（原书例题）

**例句（词性转换，原书）**："It took a long Presidential drive to get them talk again" → "在总统不顾路途遥远，驱车前往调停后，双方才恢复了对话"——long（副词→路途遥远）、Presidential（形容词→总统）、drive（名词→驱车）、talk（动词→对话）全部转换词性，执着词性对应会严重影响表达。

**例句（切分，原书）**："My father was not wrong in judging me too young to manage business of importance" → "我父亲认定我太年轻，办不了大事。他算是没说错。"——一句拆两句，层次更清晰自然。

**例句（合并，原书）**："Thank you for your advice and counsel" → "谢谢你的忠告"——两词实为一个意思，重复只是语言手段。

**例句（删词，原书）**："He shakes his head" → "他摇头"，不译"他摇着他的头"——英文语法要求的物主代词不必译出。

**例句（被动，原书）**："广告随处可见"省"被"字；"他被捕了"属强调场景例外——被动转主动还是沿用，取决于译者当下判断，无机械标准。

## A2 — 未来触发

**典型情境**：
1. 用户要翻译一段/一篇英文技术文档或文章
2. 用户问"这句怎么翻才自然""直译还是意译"
3. 用户在做技术书/文档的翻译项目，要流程和规范
4. 用户校对译文，觉得别扭但说不出原因

**语言信号**：翻译 / 怎么翻 / 直译意译 / 翻译腔 / 术语表 / translate this / technical translation / translation review / how to translate

**与相邻能力的区分**：译文的中文表达润色 → clear-expression；译文排版规范 → chinese-tech-typography；用非母语直接写作（非翻译）→ clear-expression + book-writing-engineering 的英文书经验。

## E — 执行步骤

**输入契约**：待译原文（必需）；用途与读者（缺失时询问——影响风格取舍）；术语表（多人项目必需，没有则创建）。

1. **理解**：逐句读原文，标注不确定处并查证（上下文、背景资料、求助）。完成标准：能用中文复述每句意思且无疑问；有疑问未清不得进入输出。
2. **初译**：按功能对等优先级译出——先保准确，再保易读。完成标准：无漏译、无理解性错误。
3. **五技巧过检**：词性（有无被原文词性绑架）→ 结构（长句切分/冗余合并/语序移位，短句化程度由"不失原味"约束）→ 被动（"被"字可否省/换）→ 增删词（每处增删是否增减了意思）→ 术语（与术语表一致）。完成标准：每技巧一条处理记录。
4. **脱稿校对**：收起原文，以陌生读者身份通读译文，标记"不通"处并修正。完成标准：通读无卡壳；术语、格式、注释细节同步完成不积压。
5. **交付**：译文 + 关键取舍说明（哪里选了意译、为什么）。

**输出契约**：终稿译文 + 术语表（新增条目）+ 取舍说明。

## B — 边界

- 适用范围声明：非文学翻译（技术、商业文本）；文学翻译的理解难度与风格权重大幅不同，本卡不适用。
- 时代语境：原书对机器翻译的判断基于 Google Translate 时代。大模型时代风险形态已变——机器产出"流畅但错"的译文更隐蔽，"联系上下文核对、脱稿校对、理解优先"的纪律反而更重要，不可因译文流畅而跳过理解环节。
- 短句化译法原书自注"尚存争议"：不是必须拆短句，自由度由译者把控。
- 机器翻译可辅助理解（断句、术语参考），但机器译文不可直接拿来用；照搬自己都没弄明白的译文是原书点名的失败模式。
- 非母语写作的相关经验（读者不是语言学家、意思 get 到即可、跨语言转换是重写不是直译）可作为补充参考，但那是"写作"不是"翻译"，场景别混。
