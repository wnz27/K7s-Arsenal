# 动笔前定位：说服自己、三问与场景元问题

## R — 原文

> "如有必要，我都会问 TA 几个问题：1. 我想传达什么讯息？2. 我的目标受众是谁？3. 读完以后，希望受众做点什么？大家可以在写之前，以及写之后，也自言自语问自己这几个问题。"
> ——《如何评价一篇文章》（张凯峰）

## I — 自述

动笔前只需要回答很少的问题，但必须回答清楚。第 0 问是"说服自己"：要写的内容是否自己真实经历、真实相信——连自己都说服不了的东西，写出来也无法吸引别人。然后是定位三问：传达什么讯息（一句话能说清）、目标受众是谁（具体到人，不是"所有人"）、希望受众读完做什么（行动可以是"改变一个看法"）。三问在写之前问、写完之后还要再问一遍——兼作启动与验收。

如果文章要投给特定平台/媒体，还要回答场景的"元问题"：这个媒体的读者关心什么、它的存在要回答什么问题（原书例：Thoughtworks 洞见的三元问题是"我们是怎样的公司/做什么/需要怎样的人"，所有文章都在回答其中一两个）。通用化为：投稿前先弄清目标媒体的元问题与趣味倾向，让你的选题角度与之匹配。最后按发布范围定质量标准：只给自己看，看懂即可；对外发布，必须通俗易懂、无模糊知识点、无错误、语句通顺。

## A1 — 应用示例（原书案例）

**案例（主编工作实践）**：张凯峰运营洞见七年，"每一次，有人跟我说，我想写点什么……如有必要，我都会问 TA 几个问题"——三问是他给所有投稿者的统一入口。他还给出对照：新闻报道只陈述事实、让观者自己判断；而发表个人观点的文章必须陈述观点，两者不可混淆。原文断言：即使只写给自己，能清楚回答三问的文章也"肯定好过目标受众乱，讯息不明确，却被发表出去的内容"。

## A2 — 未来触发

**典型情境**：
1. 用户说"我想写一篇关于 X 的文章"但还没想清楚怎么写
2. 用户列了几个选题，纠结写哪个、从哪个角度切入
3. 用户问"这个主题值不值得写""写给谁看"
4. 用户准备向某个平台/公众号/媒体投稿

**语言信号**：想写点什么 / 帮我理清思路 / 定位 / 选题 / 写给谁 / 怎么切入 / I want to write about / how to position this article / who is this for

**与相邻能力的区分**：选题已定、要的是写作流程 → drafting-workflow；文章已写完要评估 → article-quality-review；要发布前最终检查 → prepublish-check。

## E — 执行步骤

**输入契约**：用户的模糊写作意图（主题/素材/经历），目标发布渠道（可选）。若用户连主题方向都没有，先转素材发现（drafting-workflow 第 1 步）。

1. **说服自己门禁**：问用户——这是你的真实经历或真实相信的观点吗？如果否，建议换题或补充亲历素材；不代用户编造动机。完成标准：用户能用一两句话讲出"为什么是我来写这个"。
2. **答三问**：逐一要求一句话答案——讯息（核心观点/结论，一句话）、受众（具体到"工作几年的什么人"）、行动（读完做什么，可以是认知改变）。答不出就追问，不替用户答。完成标准：三问各有一句话答案，且互相自洽（受众×行动匹配）。
3. **场景元问题匹配**（有目标渠道时执行）：分析目标媒体/平台的定位与读者预期，列出它的 1-3 个"元问题"，确认文章回答其中哪一个。完成标准：明确"本文回答该场景的哪个元问题"；无目标渠道时跳过并标注。
4. **定质量档位**：确认发布范围（自用/小范围/公开发布/投稿），给出对应质量标准。完成标准：用户确认档位，明确本次写作的质量底线。
5. **输出定位卡**：汇总以上答案。完成标准：用户复述定位卡无异议后再动笔。

**输出契约**：定位卡一张（动机一句话 / 三问答案 / 场景元问题 / 质量档位）。

## B — 边界

- 三问管单篇，不管长期人设：原书另一位作者（李光毅）主张"风格与受众由作品创造，无法提前设定"——长期定位问题不要套用本卡强行规划。
- 元问题的原书实例是 Thoughtworks 企业媒体语境，使用时必须抽象为"目标媒体的元问题"，不照搬三个元问题。
- 本卡只管定位，不保证文章质量：三问答清只是必要条件。
- 用户只想让人代写文章、拒绝回答三问时，提示"定位不清的代写必然返工"，仍坚持先定位后写作。
