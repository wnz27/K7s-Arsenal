# 中文技术文章排版与配图规范

## R — 原文

> "1. 尽可能使用短句，使用 3-5 行以内的小段落。……4. 中英文混居，英文单词前后留半角空格。5. 一篇文章中出现的颜色、字体、字号等最好不要超过 3 种。……7. 排版体现呼吸感，特别要提出的是考虑针对移动阅读的排版。"
> ——《如何评价一篇文章》§4.1（张凯峰）

> "需要看清楚其上文字的图片一定要清晰，否则建议用文字描述代替图片展示。"
> ——《如何评价一篇文章》§4.2（张凯峰）

## I — 自述

排版是阅读体验与粘性的组成部分，尤其在移动阅读为主的场景。排版规则七条，逐条可校验：
1. 尽可能使用短句，段落控制在 3-5 行以内；
2. 文字按需适当加粗，适时引用外部文字（加粗只给真正的重点）；
3. 正确使用标点符号，多用（无）编号列表组织并列信息；
4. 中英文混排时，英文单词前后留半角空格；
5. 颜色、字体、字号合计不超过 3 种——N 种字体颜色标重点只会制造混乱；
6. 段首缩进在互联网时代已非必需，用段间距保持层次感；
7. 排版要有呼吸感，优先考虑移动阅读。

配图规则四条：① 数量克制——不影响表达的前提下少用图，非重要图片过度使用会拉低浏览量；② 图文比例——避免大篇幅独句成段和图片高频出现，以读者视角把握；③ 清晰度底线——图上文字必须看得清，看不清就改用文字描述；④ 图上文字配色从图片中取色，保持和谐。

执行上不必人肉记忆：规范层可参照《中文文案排版指北》（社区版标准），工具层可用 Pangu 类插件一键完成中英文空格等修正；图片上传前用 TinyPNG 类工具压缩（加载更快、省 CDN 与读者流量）。

## A1 — 应用示例（原书案例）

**案例（编辑观察，张凯峰）**："经常看到一些文章用 N 种字体和颜色来标示重点内容，效果适得其反。不仅没起到强调的作用，反而给人一种很混乱的感觉。"——这是"≤3 种"规则的直接来源。

**案例（反模式清单）**：大篇幅独句成段、图片高频率出现——主编明确点名的两类破坏图文比例的做法；以及"需要看清楚其上文字的图片"不清晰时，应"用文字描述代替图片展示"。

## A2 — 未来触发

**典型情境**：
1. 用户贴出文章："帮我检查/修复排版"
2. 用户问"中英文之间要不要空格""段落多长合适"
3. 用户文章图片很多/图里文字看不清
4. 用户在公众号/博客后台粘贴后格式混乱

**语言信号**：排版 / 格式乱 / 中英文空格 / 段落太长 / 配图 / typography / formatting / spacing / layout check

**与相邻能力的区分**：内容质量与结构 → article-quality-review；发布前整体把关（含脱敏）→ prepublish-check；写作工具与自动化配置 → writing-toolchain。

## E — 执行步骤

**输入契约**：待检查的文稿（必需，Markdown 或纯文本）。目标平台（公众号/博客/掘金等）缺失时询问——不同平台的渲染限制不同。

1. **段落与句子**：扫描超过 5 行的段落与超长句，给出拆分位置。完成标准：无 >5 行段落；拆分处保持语义完整。
2. **强调与标点**：检查加粗是否只用于重点、标点是否规范（全角/半角）、并列信息是否列表化。完成标准：加粗密度合理（连续段落不整段加粗）；标点无误用。
3. **中英文空格**：逐处检查英文单词、数字与中文之间是否有半角空格。完成标准：全部补全（可建议 Pangu 类工具一键处理）。
4. **颜色字体字号**：统计文内颜色/字体/字号种类数。完成标准：合计 ≤3 种；超出则给出收敛方案。
5. **段落层次**：检查段间距是否替代段首缩进、层次是否清晰。完成标准：移动端预览下有呼吸感（无整屏文字墙）。
6. **配图检查**：逐图核对——必要吗/图文比例合适吗/图上文字清晰吗/图上文字配色取自图片吗/已压缩吗。完成标准：每图一项结论；不合格图给替代方案（改文字描述/重绘/压缩）。
7. **输出**：合规稿 + 逐条检查表。

**输出契约**：修正后的文稿 + 七条排版 + 四条配图的逐项检查表（通过/已修/建议）。

## B — 边界

- 规范语境是移动阅读为主的中文技术文章；印刷出版、学术论文、文学排版的规则不同，不混用。
- 翻译场景注意：本清单第 1 条"短句"针对中文成稿阅读体验；翻译生产环节"短句是否一定好尚存争议"（原书另一篇明确标注），两处语境不要互相套用。
- "≤3 种"针对正文排版，代码块、引用块的语法高亮配色不在此列。
- 工具（Pangu/赫蹏/TinyPNG）为原书 2020 年推荐，可用当下等价物替换；规则本身长效。
- 不做内容判断：排版合规的文章仍可能是烂文章，内容问题转 article-quality-review。
