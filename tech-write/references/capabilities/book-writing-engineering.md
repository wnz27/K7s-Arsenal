# 写一本书的工程方法

## R — 原文

> "不论是写一篇简单的博客，还是写一本书，都需要按照自上而下的方式。随心所欲的写下去，基本上都收不住……先列出大的章节，然后逐步细化，但是未必是按照顺序来写。先编写自己最熟悉的部分，然后逐步完善。"
> ——《技术人员如何写一本书？》（邱俊涛）

> "写一本书也可以使用迭代交付：每一个章节作为一个迭代，每个迭代大概一个月左右。……每个迭代完成后，将写好的文稿第一时间给编辑进行预览并提出修改建议。"
> ——《用什么工具写书》（贺思聪）

## I — 自述

写书先过决策关。体裁差异：文章精简、远离细节；书要深入细节到"读者可依书自修"。经济账要算清：原书作者第一本书定价 50 元、版税 8%（每册 4 元），卖 3000 册共 1.2 万元，写了三年——"毫不合算"；技术翻译千字约 60 元，基本是公益。结论：写书动机应设为知识分享与自我成长，不是收入。发布形态用三问题检验：时滞性（交稿到出版 4-8 个月，技术内容出版即过时）、排版（出版社要 Word，跨平台格式失真）、更新频率（勘误要等再印刷）——电子书三关皆过（随时更新、模板排版、读者免费拿更新），技术书优先考虑。

结构关：自上而下——先列章节骨架再逐步细化，写作顺序不必等于阅读顺序，从最熟悉的部分先写；教程类内容按学习曲线组织（简单需求→逐步增强→在更复杂需求中复用深化），而非按知识体系罗列。注意原书内部分歧：于晓南认为瀑布式与边写边构思"无所谓好坏"，邱俊涛对写书断言必须自上而下——长文/书稿建议采纳后者。

交付关（防烂尾核心）：每章一个迭代、约一个月，一鼓作气坚持每天写；每迭代完成第一时间交编辑预览拿反馈；合规约束（如涉地图内容须审核）在早期迭代就控制，避免大规模返工。

质量关：知识的诅咒——掌握知识后无法想象无知状态，作者无法预判初学者困惑点，唯一解法是找初学者试读，且"尽可能多"的人以对冲个体偏差；错别字检查同理交给他人。大目标心态：不切实际的目的一旦开始细化并逐步实施，就已离它不远；最终结果与最初目标不完全契合属"无法掌控的部分"。

## A1 — 应用示例（原书案例）

**案例（账本，邱俊涛亲历）**：第一本书卖 3000 册 × 4 元 = 12,000 元，写了三年。对照：IBM developerWorks 投稿千字 200 元——写文章的金钱效率反而高于写书。电子书《3 周 3 页面》定价 16 元、每本实得 14.7 元，gitbook 累计下载 28,861 次、读者近 5,000，无审核无排版耗时。

**案例（迭代史，邱俊涛亲历）**：英文书起于一次客户培训的讲义，先整理成教程草稿；与编辑朋友梳理结构未果但获得清晰骨架；译成英文后持续重构，第二版几乎重写、更换工具链、更名；赴澳后当地同事以 GitHub PR 方式润色了全书约 70%——"实际使用一门语言"驱动的多轮演进。

**案例（合规前置，贺思聪亲历）**：书稿含地图图片，2018 年新规要求地图必须经审核。因每章迭代即交编辑，书稿早期就删减相关内容，"避免了大规模返工的情况"。

## A2 — 未来触发

**典型情境**：
1. 用户说"我想写一本技术书/教程"，问怎么规划
2. 用户写书写到一半坚持不下去、担心烂尾
3. 用户纠结出版方式：出版社还是自出版、实体还是电子
4. 用户书稿写完，不知道怎么保证质量

**语言信号**：写书 / 出书 / 写一本 / 教程成书 / 出版 / book writing / how to write a technical book / self-publishing / ebook vs print

**与相邻能力的区分**：单篇文章 → drafting-workflow；工具链细节（Markdown/Git/代码同步）→ writing-toolchain；文章级质量评估 → article-quality-review。

## E — 执行步骤

**输入契约**：书的主题与目标读者（必需）；可用的写作时间（缺失时询问——迭代节奏依赖它）。

1. **决策确认**：与用户对齐三件事——体裁（深入细节到可依书自修）、动机（知识分享而非收入，给出原书账本数量级参考）、形态（三问题检验：时滞/排版/更新，技术书倾向电子版）。完成标准：用户明确接受三条前提，或提出异议并记录。
2. **骨架**：自上而下列出全部章节（一级），再细化到小节（二级）；教程类按循序渐进重排（简单需求→复杂需求）。完成标准：完整两级目录；每章一句话主旨。
3. **写作顺序**：标注各章熟悉度，从最熟悉的章节先写。完成标准：排出写作顺序表（≠目录顺序）。
4. **迭代计划**：每章一个迭代约一月，每周固定写作时段；定义每个迭代的交付物（章节初稿）与反馈通道（编辑/伙伴预览）。完成标准：排出逐月迭代表；合规风险（地图/涉密/版权）在第 1 个迭代就列出并处理。
5. **试读**：成稿后招募尽可能多的初学者试读，收集困惑点清单，逐条修改。完成标准：试读者 ≥2 名且确属目标读者背景；困惑点逐条有"改/不改+理由"结论；错别字委托他人检查。

**输出契约**：决策确认记录 + 两级目录 + 写作顺序表 + 迭代计划表 + 试读反馈处理记录。

## B — 边界

- 经济口径（4 元/册、千字 60/200 元、14.7 元/本）为作者个案与 2020 年语境，仅作数量级参考，不是报价。
- 出版合规（地图审核等）为 2018 年政策，执行时核现行法规。
- 自上而下是邱俊涛对写书场景的强主张，与于晓南"模式皆可"并存——本卡采纳"书稿先骨架"，但用户若为短文写作，不要强行推广。
- 原书未讨论 AI 辅助写书；试读、迭代、合规机制在 AI 参与时依然适用，但"写作驱动学习"的收益会随代写程度衰减。
- "结果与目标不契合随他去"是心态条款，不是放弃质量标准的借口。
- 多作者合著、出版社谈判、营销发行等原书未覆盖，超出部分如实告知。
