# 传播最后一公里：物料、渠道与交互

## R — 原文

> "考虑到传播的渠道需求不同，可能要准备：1. 所属文章的一个清晰可读，便于 SEO 的 URL 链接。2. 可以作为引用文字，方便传播文章的一段话（不超过 70 字）。3. 可以作用引用图片，方便传播文章的一幅图。我把这叫做内容的最后一公里。"
> ——《如何评价一篇文章》（张凯峰）

> "对于精力有限的创作者而言，决定优先投入资源的渠道是个必须要做出的抉择。无论你此后的运营技巧多么娴熟高超，这里都会是你的起点。"
> ——《技术写作的困境》（李光毅）

## I — 自述

文章写完不等于结束，"最后一公里"是写作流程的正式组成部分。三件事：

**物料三件套**（发布前备齐）：① 清晰可读、便于 SEO 的 URL；② 一段不超过 70 字、可直接被引用的引文（写简介时可复用网页 description）；③ 一幅可引用的配图——"好的配图比标题更吸引人"。图片上传前记得压缩。

**渠道决策**（先抉择，再匹配）：精力有限，全渠道覆盖不可行——先根据内容形态与制作成本选定 1-2 个优先渠道（原书作者的取舍：长文发博客/公众号/知乎专栏，短文在 Twitter，视频因制作成本高、几次质量一般后战略性放弃）；再熟悉各渠道的品味定位与受众群，按匹配度扩展，有条件就与媒体合作投稿。发布动作标准化：各渠道发"简介 + 链接 + 配图"，发布后观察反馈并与读者交流。

**交互与迭代**：尊重读者评论、适度交互；根据积极反馈持续修改文章，形成"发布→反馈→修改→再反馈"的闭环——文章是持续演进的交付物，不是一次性发布。心态排障：没人看不代表质量差，先排查标题是否无感、选题是否曲高和寡，归因到可修复项然后继续写。

## A1 — 应用示例（原书案例）

**案例（作者渠道实验，马大伟）**：长文发博客 + 微信公众号 + 知乎专栏；Telegram 建三个主题 Channel，用机器人自动汇合进群、同步 Twitter、静态化到博客；正文写完在 Unsplash 找封面，一键推送 GitHub 自动触发发布。视频类"制作了几次质量一般的视频后，我暂时放弃了视频类的发布"——成本收益驱动的渠道取舍实录。

**案例（漏斗参照，于晓南）**：100 人推送 → 20 点开 → 10 翻看 → 5 细读 → 1-2 反馈（个人观察口径）——推广数据冷淡是漏斗常态。

## A2 — 未来触发

**典型情境**：
1. 用户文章写完/发布了："接下来怎么推广"
2. 用户问"帮我写个发布简介/推文"
3. 用户纠结发哪些平台、要不要做视频/多平台
4. 用户发了文章没反响，想知道哪里出问题

**语言信号**：怎么推广 / 传播 / 引流 / 发哪些平台 / 帮我写简介 / 渠道选择 / how to promote my article / distribution channels / write a blurb

**与相邻能力的区分**：文章还没过发布前检查 → prepublish-check；因推广数据产生情绪困扰 → feedback-and-traffic-anxiety；文章质量问题 → article-quality-review。

## E — 执行步骤

**输入契约**：已完成并通过发布前检查的文章（必需）；用户的渠道现状与精力预算（缺失时询问——渠道决策依赖它）。

1. **备物料**：产出三件套——规范 URL（含关键词、无冗参）；≤70 字引文（数清字数，含核心观点与钩子）；一幅引用图（清晰、已压缩、版权可用）。完成标准：三件齐备且可直接复制使用。
2. **渠道抉择**：列出用户的候选渠道，按"内容形态 × 制作成本 × 目标读者聚集度"打分，选 1-2 个优先渠道。完成标准：明确优先渠道与被放弃渠道及理由（成本过高是正当理由）。
3. **匹配发布**：按各渠道品味改写简介（同一引文可微调语气），执行"简介+链接+图"发布。完成标准：每个渠道一条发布记录（时间/链接/简介版本）。
4. **观察交互**：发布后约定观察期（如 48 小时），收集反馈并分类（夸赞/提问/误解/恶意）。完成标准：反馈清单；提问与误解类给出回应建议。
5. **迭代修订**：据积极反馈修订文章（补充答疑、修正错误），形成改进闭环。完成标准：一版修订记录，或明确"无有效反馈、按漏斗属常态，不改"。

**输出契约**：物料三件套 + 渠道决策表（优先/放弃+理由）+ 发布记录 + 迭代结论。

## B — 边界

- 平台清单为 2020 年语境（Telegram 机器人、gitbook、V2EX 等），执行时必须按用户当下的实际渠道重映射，不照搬原书平台清单；AI 搜索分流下 SEO 的权重也在变化。
- 漏斗数字（100→20→10→5→1-2）为个人观察口径，仅作预期校准，不作统计结论。
- 原书立场反"增长黑客"：本卡不提供刷量、标题党、互推群等技巧——那是原书明确警告的失败模式。
- 渠道优先抉择是张凯峰（多渠道广传）与李光毅（精力有限先抉择）两视角的合成：先选优先级，再在选中渠道内做匹配扩展，不要把两种建议同时执行。
- 视频的"放弃"是作者个案（制作成本与质量权衡），不是"别做视频"的普适建议。
