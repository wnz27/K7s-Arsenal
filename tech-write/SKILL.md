# 技术写作手册 — 全书能力入口

## 触发与不触发

**适用**：与本书能力域相关的咨询与任务（见下方路由表的意图列）。
**不适用**：
- 文学、小说等非技术内容创作（原书声明非文学语境）
- 纯代写、代笔、洗稿（本包提供方法论，不代替用户完成加工）
- 学术论文写作规范（原书未覆盖）
- 增长黑客式流量运营技巧（与原书立场相反）

## 核心原则（常驻速览，概览类问题读到这里即可回答）

1. 写作驱动学习：写完即兑现价值，发布与流量是副产品，别用外部数据否定写作本身
2. 动笔先定位：先说服自己，再答三问（讯息/受众/行动），并匹配目标场景的元问题
3. 质量是唯一可持续策略：五维自评、三遍审读、发布前必脱敏
4. 写作是工程：自上而下、迭代交付、初学者试读对抗知识的诅咒、纯文本加版本管理
5. 传播是写作流程的一部分：最后一公里物料三件套，渠道先抉择再匹配
6. 长期主义预期管理：反馈漏斗与存款模型校准预期，负面反馈分类处置而非情绪化反应

## 加载规则

- 每次任务先读本文件，再按路由表加载 **1** 张能力卡；任务明确跨域时最多加载 2 张。
- 概览/书名类问题不加载能力卡，用「核心原则」与 overview.md 回答。
- 路由表与 capability-index.md 都无法命中的意图，明确告知超出本书范围，不要硬套。

## 边界与判停

- 用户素材或上下文不足且无法补充时，先询问，不编造书中没有的方法
- 涉及合规判断（脱敏边界、版权、地图等出版规定）不确定时，提示核对现行法规与组织流程
- 用户请求超出原书范围时，明示超出并降级为标注来源的通用建议
